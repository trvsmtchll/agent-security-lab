# Security & Safe Use

This repository is a **deliberately vulnerable** teaching lab. It exists to demonstrate
agentic prompt-injection attacks and the controls that stop them. Read this before running.

## What is intentionally dangerous

- **`run_command` executes real shell commands** in the agent container (`shell=True`).
- **`query_database` runs arbitrary SQL** against the bundled PostgreSQL instance.
- **`fetch_webpage` fetches arbitrary URLs** — this is the injection entry point.
- The agent is *designed* to be talked into misusing all of the above.

None of this is a vulnerability to report — it is the subject of the demo.

## How it is kept safe by default

- **Synthetic data only.** The `customers` database is generated by Faker with a fixed
  seed. There is no real PII anywhere in this repo.
- **Local sinks only.** The default exfiltration target is the bundled `attacker-server`
  container. `push_to_github` is inert unless you deliberately supply a `GITHUB_PAT`.
- **Localhost binding.** Every published port in `docker-compose.yml` binds to
  `127.0.0.1`. Nothing is exposed to your LAN.
- **Offline default.** `DEMO_MODE=scripted` ships as the default and makes no external
  network calls or LLM requests.

## Rules for running it

1. Run it on a machine you control, ideally a disposable VM or an isolated Docker host.
2. Do **not** deploy it to a shared or internet-reachable cluster. If you deploy to
   Kubernetes, use a throwaway namespace in a cluster you own.
3. Never point its tools or credentials at anything real — no production databases, no
   real GitHub org, no corporate network.
4. Do not commit a populated `.env`. Only `.env.example` (placeholders) is tracked, and a
   gitleaks scan runs in CI and as a pre-commit hook.

## Reporting

If you find a way this lab could cause harm *outside* its sandbox (e.g. a default that
reaches the network unexpectedly), open an issue.
